## 1. QEMU emulation

The faithful AST2050 model is the QEMU machine **`kgpe-d16-bmc`** in the
[`mithro/qemu` fork, branch `claude/bmc-functionality`](https://github.com/mithro/qemu/tree/claude/bmc-functionality)
(submodule at [`asus-kgpe-d16-firmware/qemu-firmware/qemu/qemu`](https://github.com/mithro/ai-shenanigans-for-bmcs/tree/claude/bmc-functionality/asus-kgpe-d16-firmware/qemu-firmware),
pinned to [`afb611e129`](https://github.com/mithro/qemu/commit/afb611e129e9a47bf876ce115b1f7189905f427b)).
The AST2050 is **not supported by upstream QEMU** (earliest Aspeed SoC is the AST2400/G4); the G3 SoC class (`aspeed_soc_ast2050`, silicon-rev `0x00000202`) was built by specializing the AST2400 code with G3-faithful differences, validated against the
[AST2050 datasheet](https://github.com/mithro/ai-shenanigans-for-bmcs/blob/claude/bmc-functionality/dell-c410x-firmware/datasheets/) and real-silicon reads.
The per-peripheral model program was integrated via [PR #25](https://github.com/mithro/ai-shenanigans-for-bmcs/pull/25); its integration suite reached **108 passed / 0 xfailed on 2026-07-13**, with further tests added since (e.g. the [H-PLL rate test](https://github.com/mithro/ai-shenanigans-for-bmcs/blob/claude/bmc-functionality/asus-kgpe-d16-firmware/qemu-model/integration/test_timer.py)).

### 1.1 Firmware boot oracles (all pass in CI)

The governing principle: *the legacy/proprietary firmware is the faithfulness oracle and must always keep booting* — a change that breaks a legacy boot is a model bug, never a firmware bug.

| Oracle | Firmware | Proves | CI job ([workflow](https://github.com/mithro/ai-shenanigans-for-bmcs/blob/claude/bmc-functionality/.github/workflows/d16-qemu-stack.yml)) |
|---|---|---|---|
| **C2** | Our U-Boot → Linux v6.6.70 → dropbear SSH | Modern full chain on the faithful machine | `boot-ssh`, `boot-uboot-ssh` |
| **C3** | Raptor 2.6.28.9 kernel + musl userspace → SSH | Vintage-kernel compatibility (Raptor's real AST2050 port) | `boot-raptor` |
| **C4** | **Dell vendor firmware** (proprietary, from [committed archives](https://github.com/mithro/ai-shenanigans-for-bmcs/tree/claude/bmc-functionality/dell-c410x-firmware/backup)) → appweb web service | The strictest faithfulness oracle | `boot-c4-web` |
| **C-UBOOT** | **Raptor G3-native U-Boot** (real SCU + DDR2 lowlevel_init) → `boot#` prompt | Reset-table + DRAM-controller faithfulness (via the default-off `g3-resets` SCU property) | `boot-uboot-scu` |

**Standing constraint:** the BMC's SPI-flash socket is **empty** on this bench — all silicon testing boots the BMC into **volatile DRAM over JTAG or P2A** (no persistent firmware). Consequences: `BMC_PRESENT#` strap sits high (SOL mux + I2C mux-ownership side-effects), P2A boot reliability degrades after ~15 cycles, and DRAM is shared with the host VGA framebuffer (fragility around host POST).
