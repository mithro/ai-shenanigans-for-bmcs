DEVICE-MATRIX row 44 (MIC) — REAL-SILICON cross-validation: PASS (BIT-EXACT vs the QEMU model)
=============================================================================================

The QEMU aspeed_mic_ast2050 model was cross-validated against the REAL AST2050 MIC
hardware over JTAG (SPI flash is not connected, so silicon testing is JTAG-driven).
The real chip computes the IDENTICAL bit-exact Fletcher-32 the model produces, and
detects a checksum mismatch with the correct page number — the strongest possible
faithfulness evidence ("the hardware is 100% reliable; is my model faithful?" -> yes,
bit-for-bit).

Method: on the bridge Pi (rpi4-asus-aspeed2050-dev), 3 OpenOCD steps —
  1. reset halt (clean core, MMU off)
  2. ddr2-init.tcl (re-train DDR2 — a core reset clears the SDMC)
  3. mic-test-silicon.tcl (this dir): AHB unlock (0xAEED1A03) + DRAM->0x0 remap,
     the SLT's vInitSCU MIC reset-release (SCU04 &= 0xbffff), lay out a zeroed 4KB
     page (page 15) + control buffer (page15=MIC-mode, rest SKIP) + checksum buffer,
     enable the MIC, read back the checksum, then corrupt the page and re-scan.

FAITHFULNESS LESSON (governing principle in action): the first run had the MIC NOT
scanning (checksum stayed 0). That was MY incomplete driving, not a hardware fault —
the Raptor SLT's vInitSCU() (mictest.c) does `SCU04 &= 0xbffff`, which RELEASES THE
MIC FROM RESET (SCU04 bit 18). Adding that one step made the real MIC scan. The
hardware was reliable; my JTAG sequence was missing the reset-release.

Result vs the QEMU model (evidence 01-mic-fletcher32-qemu-PASS.txt):
  - zero-page checksum: silicon 0xFFFFFFFF == model 0xFFFFFFFF  (bit-exact)
  - mismatch -> first-page-error flag + recorded page number: silicon 0x1000000f
    (flag+page15) == model 0x10002000 (flag+page8192) — same mechanism, the page
    number differs only because the silicon test used a smaller scan (page 15 vs 8192).

Conclusion: the QEMU MIC model (Fletcher-32, control-buffer skip/check, checksum-
buffer store, first-page-error escalation) is faithful to real AST2050 silicon —
validated in QEMU (evidence 01) AND on the real chip (this file). It also confirms
the AHBC protection-key + boot-remap (rows 45/49) on real hardware.
