# CONCLUSION: the AST2050 BMC does NOT self-boot from its own flash -- AC power
# alone yields no console and no network. This is consistent with the project's
# established boot story: the BMC is brought up EXTERNALLY, either
#   (a) P2A/culvert -- requires the x86 HOST booted first (blocked: dead CMOS
#       battery halts every host boot at F1/F2; Intel Boot Agent cannot multi-file
#       TFTP -- see d16-host-pxe-boot notes), or
#   (b) JTAG (openocd, ~/openocd-bmc, proven 2026-07-10: IDCODE 0x07926f0f, halt,
#       AHB mdw) -- DDR2 init + load kernel.
#
# THEREFORE the silicon USB test (Test A in USB-REAL-HW-VERIFICATION.md) cannot be
# reached with power-on/off authority alone: there is no running BMC to export the
# gadget. Completing it requires bringing the BMC up via JTAG/P2A, i.e. run-control
# + memory operations on the board -- a more invasive class than power on/off and
# NOT covered by the current authorization (an openocd first-contact/scan_chain was
# attempted and correctly gated).
