DEVICE-MATRIX row 24 (PSU PMBus) / #198 — phantom sensors FIXED: PASS
=====================================================================

The phantom in2(vcap)/temp2/temp3 = -500 sensors (reproduced + root-caused in
01-phantom-sensors-REPRODUCED.txt) are ELIMINATED. QEMU submodule 918836e937.

FIX: a real PSU NACKs unsupported command codes, but QEMU's SMBus slave could not
(smbus_slave.c discarded write_data's return; the per-byte send always ACKed).
Added an OPTIONAL SMBusDeviceClass::check_command(dev, cmd) hook, called on the
first (command) byte of a write phase — return non-zero to NACK. Default NULL =
historical ACK-everything, so every existing SMBus device is unaffected (opt-in,
contained). pmbus_psu.c NACKs READ_VCAP / READ_TEMPERATURE_2 / READ_TEMPERATURE_3.
The NACK on the command byte aborts the read-word, so Linux's pmbus_check_word_
register() gets rv<0 and treats the sensor as ABSENT (instead of reading 0xFFFF as
present).
