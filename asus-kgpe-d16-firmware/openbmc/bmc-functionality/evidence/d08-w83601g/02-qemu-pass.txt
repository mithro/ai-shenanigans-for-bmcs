expanders (hw/gpio/w83601g.c) over the BMC's direct I2C5 engine (Linux i2c-4)
exactly as firmware does on silicon — raw SMBus register access, no driver. All
19 assertions pass against the Nuvoton V1.31 datasheet + silicon captures:

Model bug found + fixed during bring-up: the 34-register file (0x22) is not a
power of two, so an `& (NR_REGS-1)` pointer mask (copied from the 8-register
jc42 model) aliased CR02->CR00 etc. Replaced with an explicit range check; the
pointer is a plain uint8_t that wraps mod 256 like the hardware.
