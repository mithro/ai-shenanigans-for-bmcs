# --- sysfs-driver diagnostic (kgpe-power.sh on/off directly, bypassing op-pwrctl) ---
# Even the DIRECT kgpe-power.sh on leaves gpioH2=False in QEMU, though it is PROVEN
# on silicon (plug 3W->103W, host powers on). So the power-ON gap in QEMU is NOT
# just op-pwrctl: kgpe-power.sh's in-guest GPIO drive (sysfs /sys/class/gpio + the
# SCU74[25] A4 reclaim + B1 pulse) does not reach the modeled GPIO latch. NB: the
# bare-metal fwtest/pytest test_power (which drives A4/B1 directly at the register
# level + the on_blocked_without_a4 negative check) DOES pass -- so the MODEL's
# power-on latch is correct; the gap is the guest kgpe-power.sh GPIO path vs the
# model (likely sysfs gpiochip-base / line mapping, or the exact write sequence).
# CONCLUSION for feature 1 (power) in QEMU: latch on/off validated via test_power;
# Redfish PowerState readback fixed (this file); the Redfish/kgpe-power.sh ON round-
# trip is the remaining QEMU integration gap (characterized), alongside silicon #95.

# --- ROOT CAUSE of the QEMU power-ON gap (QMP-verified) ---
# After kgpe-power.sh init + on, QMP qom-get on the model showed: gpioA4=False,
# gpioB1/F0/B6=True, gpioH2=False. So A4 (the BMC-in-control gate) never reaches
# the modeled GPIO latch, while B1/F0/B6 (banks B/F) do. Cause: A4 defaults to the
# PHYLINK pinmux; kgpe-power.sh clears SCU74[25] with devmem, but that does NOT
# update the kernel pinctrl view, so the sysfs `gpio export` of A4 fails -> A4 is
# never driven. PROOF the model is correct: driving A4 AND B1 via DEVMEM directly
# (bypassing sysfs) -> QMP gpioA4=True, gpioB1=False, gpioH2=True (power ON).
# WHERE THE FIX BELONGS (corrected 2026-07-16): a devmem A4 drive in the firmware
# was TRIED and REVERTED -- it would REGRESS silicon. On silicon A4 is driven via
# SYSFS at gpio-init, which places A4 in the kernel's bank-A-D output *shadow*, so
# it SURVIVES op-pwrctl's later sysfs B1 writes to the same register (0x1E780000).
# A raw devmem A4 sits OUTSIDE that shadow and would be clobbered the instant
# op-pwrctl drives B1 -> it breaks the hardware-verified (2026-07-13) integrated
# power-ON. Per the project's faithfulness oracle rule, the QEMU model NOT honoring
# the sysfs A4 drive (that silicon honors) is a MODEL-SIDE gap to fix in QEMU/DTB
# (e.g. free GPIOA4 in the modeled pinctrl so a sysfs export succeeds), never a
# reason to change this silicon-proven script. setup_a4 therefore KEEPS the sysfs
# drive. Net feature-1 state: OFF + readback proven both sides; integrated ON is
# the #95 item both sides; the QEMU-model sysfs-A4 faithfulness gap is the fix site.
